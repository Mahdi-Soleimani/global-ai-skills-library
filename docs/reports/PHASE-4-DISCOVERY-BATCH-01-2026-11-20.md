# Phase 4 — Commit-pinned discovery, batch 01

Date: 2026-11-20. Baseline: 4c7534a. Scope: ten repositories selected from the four independent research continuation notes. This is metadata enumeration, not content extraction, installation, or recovery of the missing source databases.

## Selection and implementation

- Read the original EN-675 and FA-234 continuation notes and the embedded checkpoints in AUX-FA-750PLUS and AUX-FA-438.
- Selected Microsoft, NVIDIA, AWS HCLS, phuryn, Adobe, Databricks, Salesforce, GitHub awesome-copilot, Google DeepMind science-skills, and deanpeters Product-Manager-Skills. The latter two were absent from the previous repository snapshot.
- Added `config/discovery-targets.json`, `tools/discover.py`, and regression tests. Research leads are not membership assertions about the original skill records.
- For each repository, retrieve GitHub repository metadata, branch commit and the exact root tree SHA from the commit response, and enumerate the complete tree by its SHA. Require matching tree identity and non-truncated response.
- Record each SKILL.md path, Git blob SHA, file mode, reported size, extraction status, source leads, date, and repository-level license metadata. Reject unsafe or repeated paths; exclude known fixture paths and non-regular files from the queue.
- Save successful observations under commit-keyed local checkpoints. Re-running skips existing observations; error retry is explicit. No automatic update to newer commits.
- Build a metadata-only queue keyed by repository, path and commit. A matching existing complete package is only identified by metadata, not approved.
- Keep detailed observations and queue ignored by Git; publish only aggregate summary and project code. The earlier source-verification snapshot and all four archives remain unchanged.
